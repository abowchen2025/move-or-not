## 1. 專案目的

用 16-bit 復古遊戲風格的網頁，以詼諧、諷刺的方式記錄「某單位要不要搬到台中辦公室」這件事：
管理層喊了好幾次要搬，但每次都沒搬成，員工只能一直等。網頁把它包裝成一則「職場鬼故事」。

### 1.1 背景時間線（已去識別化）

| 日期 | 發生的事 |
|---|---|
| 2026-10-13 | 管理部開會，事前沒溝通，直接宣布單位要搬到台中辦公室，且不接受提問。 |
| 2026-10-23 | 主管說這天搬，結果遇到颱風假。 |
| 2026-10-28 | 主管說這天搬。管理部遲遲不給台中辦公室的磁卡與鑰匙，快下班才派人送來簽收；接著傳出要先跟總經理報告才能決定，當天不搬。 |
| 2026-10-29 ~ 10-30 | 沒有人再提起搬家。 |

### 1.2 範圍

**包含：**
- 一個公開網頁（GitHub Pages），任何人都能看到相同的天數與記錄。
- 一支小型 API（Railway），保存記錄、提供台灣時間。
- 管理者（只有一人）用密語新增、修改、刪除記錄。
- 預留「多季」擴充：第一季「今天搬家沒？！」完結後，可以開新的一季、換主題與主角，第一季保留並可回放（§3.3）。**本次只開發第一季**，季別切換畫面不在本次範圍。

**不包含（Non-goals）：**
- 使用者帳號系統、多管理者、留言或投票功能。
- 資料庫（改用 JSON 檔存在 Railway Volume）。
- 多語系（只有繁體中文）。
- 任何追蹤或分析碼。

## 2. 去識別化規定 【規定】

網頁公開在網路上，網址也猜得到，所以：

1. 頁面、程式碼、commit 訊息、種子資料**不得出現**公司名稱、品牌名稱、員工姓名或暱稱、統編、地址。
2. 職稱與部門使用通用稱呼：「主管」「管理部」「總經理」「某單位」。
3. 不提及任何特定員工的去留。
4. 頁尾必須有免責聲明（文案見 FR-09）。
5. 頁面加上 `<meta name="robots" content="noindex, nofollow">`，並提供 `robots.txt` 禁止爬取。

### 3.3 內容與程式分離（為多季預留） 【規定】

目的：第一季完結後，若要開第二季（例如換成「我離職沒？！」、主角換成另一個角色），只需要**新增設定檔與圖檔**，不必修改程式邏輯。

**規則 1：劇本設定檔**
- 畫面上**所有**文字都從該季的劇本設定檔讀取（`web/src/stories/season-1.ts`），包括：標題、天數標籤、統計用語、今日狀態文案、按鈕文字（「提了」「有搬」「沒搬」）、確認對話框、錯誤訊息、免責聲明、完結文字、回放文字、分享預覽的 `og:title`／`og:description`、讀取中文案。
- 程式碼中（`stories/` 以外）**不得出現**任何主題相關的字詞，例如「搬」「台中」。驗收方式見 AC-30。
- 劇本設定檔需有 TypeScript 型別定義（`StoryConfig`），少填欄位時編譯失敗。

**規則 2：主角用外部圖檔**
- 主角（第一季為幽靈）是外部的 sprite sheet 圖檔加一份動畫描述檔，**不得**用程式碼逐點繪製角色。
- 動畫描述檔至少包含：單格尺寸、各動作的影格範圍與速度（例如 `move`、`idle`）、預設放大倍率。
- 劇本設定檔指定主角的**移動方式**：`float`（飄浮：正弦上下浮動，第一季使用）或 `walk`（走路：隨步伐輕微起伏）。本次只需實作 `float`，但程式要能依設定切換，新增 `walk` 時不需改動移動範圍、轉向、減少動態等既有邏輯。
- 劇本設定檔指定**完結演出**種類：本次只實作 `purify`（淨化成光點消失）；演出以模組方式實作，之後可新增其他種類（例如背包走出畫面）。
- WebGL 不支援時的 CSS 退路動畫，使用同一張 sprite sheet。

**規則 3：資料分季**
- 每一季一個資料檔：`${DATA_DIR}/seasons/<seasonId>.json`，第一季的 `seasonId` 為 `season-1`。
- 季別清單與各季的起始日、天數算法、種子檔，寫在 `api/seasons.config.json`（進版控）。
- 所有讀寫記錄的 API 都帶季別（§7）。
- 只有一季時，畫面**不顯示**季別選擇；預設顯示「最新一季」。之後新增季別時的切換畫面另訂規格（Q-07）。
- 前端以網址參數 `?season=<seasonId>` 指定季別；未指定時用最新一季。`#replay` 回放的是目前顯示的那一季。

## 4. 時間與天數規則 【規定】

這是本專案最容易出錯的地方，請逐條實作並寫測試。

### 4.1 時間來源

1. **台灣時間（Asia/Taipei，UTC+8）是唯一的「今天」定義。** 訪客在美國、日本打開網頁，看到的天數與今天日期都必須一樣。
2. **伺服器時間是權威來源**。`GET /api/state` 回傳 `serverNow`（含 `+08:00` 的 ISO 8601 字串）與 `today`（`YYYY-MM-DD`）。
3. 前端取得 `serverNow` 後，計算 `offset = Date.parse(serverNow) - Date.now()`，之後所有「現在」都用 `Date.now() + offset`，**不直接信任訪客電腦的時鐘**（訪客時鐘可能設錯）。
4. 前端每 10 分鐘、以及分頁從背景回到前景（`visibilitychange`）時，重新呼叫 `/api/state` 校正 offset 與資料。
5. API 連不上時的退路：用訪客時鐘換算 Asia/Taipei（`Intl.DateTimeFormat` 指定 `timeZone: 'Asia/Taipei'`）計算天數，並在頁尾顯示「⚠ 時間來源：本機時鐘」。

### 4.2 天數公式

```
起始日 START_DATE = 該季的 startDate（第一季為 2026-10-13，台灣日期）
今天   today      = 台灣時間的日期
已經過了 N 天      = today − START_DATE（以「日曆日」相減，不看時分秒）
```

| 台灣時間 | N |
|---|---|
| 2026-10-13 任何時刻 | 0 |
| 2026-10-30 23:59:59 | 17 |
| 2026-10-31 00:00:00 | 18 |

- 計算時只用日期部分相減，不要用「毫秒差 ÷ 86400000」（避免邊界誤差）。
- 【待確認】是否要「含當天」（10/30 顯示 18）。暫定：**不含當天，10/30 顯示 17**。把這個選項做成各季設定 `countInclusive: false`（`api/seasons.config.json`）。
- `startDate` 與 `countInclusive` 只存在 `api/seasons.config.json` 一處，前端一律從 API 取得，不在前端重複設定。

### 4.3 跨日即時更新

- 頁面開著跨過台灣時間 00:00 時，**不需重新整理**，天數要自動 +1，「今天提搬家沒？」區塊要重置為新的一天的狀態。
- 實作方式：每秒用校正後時間檢查台灣日期是否改變，改變時重新抓 `/api/state`。

### 4.4 真的搬了之後

- 當記錄中出現任何一筆「執行＝是」，天數**凍結**在那一天：`N = 搬家日 − START_DATE`。若有多筆「執行＝是」，以**最早**的那天為搬家日。
- 因為可以補記過去日期，搬家日可能早於今天；例如 11/5 才補記「11/3 有搬」，天數就停在 11/3 那天的值。
- 天數區塊改顯示「歷時 N 天，終於搬了」（文字來自劇本設定檔）。
- 「搬家日」在 API 中稱為 `endedDate`，「已完結」稱為 `ended`（§7.3）。
- 【待確認】搬家後的「完結畫面」演出（暫定：幽靈被淨化成光點消失，標題下出現「— 全劇終 —」）。
- 【規定】完結畫面必須提供「▶ 回放劇情」按鈕，讓訪客重看整段過程（見 FR-13）。完結之後，連載期間的動畫只能透過回放再看到。

## 5. 資料模型 【規定】

### 5.0 季別設定 `api/seasons.config.json`（進版控）

```json
{
  "seasons": [
    {
      "id": "season-1",
      "startDate": "2026-10-13",
      "countInclusive": false,
      "seedFile": "seed/season-1.seed.json"
    }
  ]
}
```

- `id` 只能是小寫英數與連字號。
- 清單順序即季別順序，最後一筆為「最新一季」。
- 季別的標題、文案不放這裡（放前端劇本設定檔），API 只管日期與資料。

### 5.1 各季資料檔 `${DATA_DIR}/seasons/<seasonId>.json`

```json
{
  "schemaVersion": 1,
  "seasonId": "season-1",
  "records": [
    {
      "date": "2026-10-13",
      "proposed": true,
      "executed": false,
      "note": "起始日",
      "updatedAt": "2026-10-30T10:00:00+08:00"
    }
  ]
}
```

| 欄位 | 型別 | 規則 |
|---|---|---|
| `date` | string `YYYY-MM-DD` | 主鍵，一天最多一筆；`START_DATE ≤ date ≤ 台灣今天` |
| `proposed` | boolean | 畫面顯示「提出：是／否」 |
| `executed` | boolean | 畫面顯示「執行：是／否」；**`executed = true` 時 `proposed` 必須為 `true`** |
| `note` | string | 選填，去頭尾空白後 0～100 字；只能是純文字 |
| `updatedAt` | string ISO 8601（+08:00） | 伺服器寫入時自動產生 |

### 5.2 種子資料（第一次啟動時寫入）

啟動時逐一檢查 `seasons.config.json` 的每一季：Volume 上沒有該季資料檔時，用該季的 `seedFile` 建立；沒有指定 `seedFile` 就建立空記錄。已存在時**絕不覆蓋**。

第一季種子檔為 `api/seed/season-1.seed.json`：

| 日期 | 提出 | 執行 | 備註 |
|---|---|---|---|
| 2026-10-13 | 是 | 否 | 起始日 |
| 2026-10-23 | 是 | 否 | 颱風假 |
| 2026-10-28 | 是 | 否 | 主管、管理部、總經理喬不攏 |

（10/30 沒有記錄，頁面會顯示「今天還沒人提」。）

### 5.3 稽核紀錄 `audit.jsonl`

每次寫入（新增、修改、刪除）在 `${DATA_DIR}/audit.jsonl` 追加一行：`{"at": ..., "seasonId": ..., "action": "upsert|delete", "date": ..., "before": {...}|null, "after": {...}|null}`。只增不改，用來事後追查與還原。不記錄 IP 或任何個資。

### 5.4 寫入安全

- 原子寫入：先寫暫存檔，`fsync`，再 `os.replace()` 蓋過正式檔。
- 單一程序內用 lock 串行化寫入。
- 讀檔失敗（JSON 損毀）時 API 回 500 並在 log 記錄，**不得**自動用種子資料覆蓋。

### 5.5 統計（由 API 計算）

| 欄位 | 定義 | 畫面範例 |
|---|---|---|
| `proposedCount` | `proposed = true` 的筆數 | 喊搬 3 次 |
| `executedCount` | `executed = true` 的筆數 | 實際搬 0 次 |
| `successRate` | `executedCount ÷ proposedCount`，四捨五入到整數百分比；分母為 0 時為 0 | 達成率 0% |

### FR-01 標題 【規定】

- 文字固定為「今天搬家沒？！」（全形問號與驚嘆號）。
- DOM 文字（`<h1>`），使用像素字型，置中。
- 字級為 12px 的整數倍（俐方體字身框為 12×12，整數倍才不會糊）：桌機 48px，手機 36px 【建議】。

### FR-02 主角（第一季：幽靈） 【規定】

以下規格中的「幽靈」即第一季的主角。移動範圍、轉向、自適應、減少動態、退路等規則，對每一季的主角都適用；外觀、影格、移動方式由該季劇本設定檔與 sprite 描述檔決定（§3.3 規則 2）。

| 項目 | 規格 |
|---|---|
| 位置 | 標題正下方的一條「幽靈跑道」 |
| 水平範圍 | 幽靈的左緣不小於標題文字左緣，右緣不大於標題文字右緣（以標題文字的實際寬度為準，不是整個 `<h1>` 區塊寬度） |
| 外觀 | 白色像素幽靈，原始尺寸 16×16 邏輯像素，整數倍放大（桌機 ×3、手機 ×2），最近鄰取樣，邊緣不可模糊 |
| 圖檔 | `web/public/sprites/ghost.png`（sprite sheet）＋ `ghost.json`（單格尺寸、動作影格、速度、放大倍率）；不得用程式碼繪製 |
| 動作 | 左右來回等速移動，走完一趟約 5 秒；碰到邊界時轉向，圖像左右翻轉讓它面向前進方向 |
| 漂浮 | 移動方式 `float`：垂直方向正弦上下飄動，振幅 ±2 邏輯像素，週期約 1.5 秒（振幅、週期寫在劇本設定檔） |
| 動畫影格 | 至少 2 格（裙襬擺動），每格約 250ms |
| 自適應 | 視窗縮放、字型載入完成、旋轉手機時，重新計算標題寬度，幽靈仍在範圍內 |
| 減少動態 | 系統設定 `prefers-reduced-motion: reduce` 時，幽靈停在標題正中央，只保留緩慢的透明度呼吸 |
| 退路 | 瀏覽器不支援 WebGL/WebGPU 時，改用 CSS 動畫顯示同一張幽靈圖，功能不受影響 |
| 搬家後 | 見 §4.4 |

【建議】PixiJS canvas 以 `position: fixed` 鋪滿整個視窗、放在 DOM 後面當背景層（星空、粒子），幽靈畫在同一個 canvas，每一幀用標題的 `getBoundingClientRect()` 換算位置，捲動時跟著標題走。也可以只在標題區放一塊小 canvas，由 RD 判斷。

### FR-03 天數 【規定】

- 顯示「已經過了 **N** 天」，N 用大號數字（強調色）。
- 下方小字：「（自 2026/10/13 起算，台灣時間）」。
- 計算規則依 §4。
- 數字變化時（例如跨日）播放一次「跳數字」動畫 【建議】。

### FR-04 統計 【規定】

一行顯示：「喊搬 X 次｜實際搬 Y 次｜達成率 Z%」，數值依 §5.5。

### FR-05 今天提搬家沒？（今日狀態） 【規定】

依「台灣今天」是否有記錄，顯示以下其中一種：

| 今天的記錄 | 狀態文案 | 按鈕「提了」 |
|---|---|---|
| 沒有 | 今天還沒人提 | 顯示 |
| `proposed=true, executed=false` | 今天提了，沒搬 | 顯示（可改成「有搬」） |
| `proposed=true, executed=true` | 今天提了，**真的搬了！** | 隱藏，改為完結演出（§4.4） |
| `proposed=false` | 今天還沒人提 | 顯示 |

> 只要任何一天（含補記的過去日期）有「執行＝是」，就進入完結狀態（§4.4），「提了」按鈕隱藏；之後要修正只能透過管理模式（FR-08）。

### FR-06 「提了」按鈕與選單 【規定】

流程：

```
按「提了」
  └─▶ 出現選單：
        日期：[ 10/30（五） ▼ ]   ← 預設台灣今天，可改（補記忘了按的日子）
        [ 有搬 ] [ 沒搬 ]
        備註：[            ]      ← 選填，最多 100 字
        [ 取消 ]
        └─▶ 選「有搬」或「沒搬」
              ├─ 已通過管理密語驗證 → 送出 PUT /api/records/{選定日期}
              └─ 尚未驗證 → 跳出密語輸入框
                    ├─ 正確 → 記住於 sessionStorage（關閉分頁即失效）→ 送出
                    └─ 錯誤 → 顯示「權限不足：你不是可以決定搬不搬的人。」
```

**日期欄位：**
- 預設值：台灣今天（依 §4.1 校正後的時間，不是訪客電腦的日期）。
- 可選範圍：`START_DATE` ～ 台灣今天。不能選未來日期，也不能選起始日之前的日期。
- 顯示格式 `MM/DD（週X）`；用原生 `<input type="date">` 並設定 `min`／`max` 即可，外觀套用像素風樣式 【建議】。
- 選的日期不是今天時，選單標題改為「補記 10/28（三）」，讓使用者清楚知道在補記。
- 選單每次打開都重設為今天，不沿用上次選的日期。

**寫入規則：**
- 寫入內容：`proposed = true`、`executed = 選擇結果`、`note = 輸入值`，寫到選定的日期。
- 選定日期已有記錄時，覆蓋前要確認，並顯示原本的內容：「10/28 已經記過了（提了，沒搬，備註：主管、管理部、總經理喬不攏），要改成 有搬 嗎？」。備註欄留空時，**保留原備註**；要清空備註請改用管理模式（FR-08）。
- 選「有搬」需二次確認：「確定 10/28 真的搬了？這可是會讓天數停在那一天的。」
- 送出成功後，若選定日期不是今天，顯示提示「已補記 10/28（三）」；今日狀態（FR-05）只反映今天的記錄，不受補記影響。
- 選單樣式：SNES 角色扮演遊戲的指令選單，▶ 游標指向目前選項，可用方向鍵、Enter、Esc 操作，手機可點選。
- 送出成功後立即重新抓 `/api/state` 更新畫面。
- 送出失敗（網路、伺服器錯誤）時顯示錯誤訊息，選單不關閉，讓使用者可重試。

### FR-07 搬家記錄表 【規定】

- 標題「搬家記錄」。
- 欄位：日期、提出、執行、備註。
- 排序：新到舊（最新的在最上面）。
- 日期顯示 `MM/DD（週X）`，例如 `10/28（三）`。
- 「是」用綠色、「否」用紅色，另附文字，不能只靠顏色區分。
- 備註一律用 `textContent` 輸出，不可用 `innerHTML`（避免 XSS）。
- 手機（寬 360px）上不得出現水平捲軸；備註過長時自動換行。
- 沒有任何記錄時顯示「尚無記錄」。

### FR-08 管理模式 【規定】

- 進入方式：頁尾一個不顯眼的「🔑」圖示，或網址加上 `#admin`。點了先驗證密語。
- 驗證後，記錄表每列出現「編輯」「刪除」，表格上方出現「新增記錄」。
- 新增／編輯表單欄位：日期（`START_DATE` ～ 台灣今天，不能選未來）、提出（是／否）、執行（是／否）、備註。
- 前端與 API 都要檢查：執行＝是時，提出必須為是。
- 刪除前要確認。
- 有「登出」按鈕，清除 sessionStorage 的密語。

### FR-09 頁尾 【規定】

- 免責聲明：「本故事純屬虛構，如有雷同，那應該就是真的。」
- 最後更新時間（取全部記錄中最新的 `updatedAt`）。
- 時間來源標示：正常時不顯示；退路模式顯示「⚠ 時間來源：本機時鐘」。
- 🔑 管理入口。

### FR-10 資料同步 【規定】

- 進入頁面時抓 `/api/state`。
- 頁面開著時每 60 秒重新抓一次；分頁回到前景時立即抓一次。
- 讓所有訪客在 1 分鐘內看到管理者的最新記錄。
- **不使用 localStorage 存放記錄或天數**（只允許用 sessionStorage 存管理密語）。

### FR-11 載入與錯誤狀態 【規定】

| 情境 | 畫面 |
|---|---|
| 讀取中 | 像素風「讀取存檔中…」閃爍文字 |
| API 連不上 | 「伺服器正在睡覺（讀取失敗）」＋「重試」按鈕；天數改用退路計算（§4.1-5）；記錄表顯示「暫時看不到記錄」 |
| Railway 冷啟動較慢 | 讀取中狀態最長等 15 秒才判定失敗 |

### FR-12 分享預覽 【規定】

同事多半會從 LINE 打開，需要好看的分享預覽：

- `og:title`：今天搬家沒？！
- `og:description`：一則還在連載的職場鬼故事。
- `og:image`：1200×630 像素風圖片（標題＋幽靈），放在 `web/public/`。
- favicon：幽靈圖示。

### FR-13 劇情回放 【規定】

把從起始日到現在的過程，照日期順序像遊戲過場一樣重播一次。結局之後，這是重看連載期間動畫的唯一方式。

**入口：**

| 入口 | 何時出現 | 標記 |
|---|---|---|
| 完結畫面的「▶ 回放劇情」按鈕 | 完結後（§4.4） | 【規定】 |
| 「搬家記錄」區塊標題旁的「▶ 劇情回顧」 | 連載中也有 | 【建議】 |
| 網址加上 `#replay` | 隨時，打開就直接開始回放，方便分享 | 【規定】 |

**演出流程：**

```
進入回放
  ├─ 畫面上方顯示「◀◀ 回放中」標示；「提了」按鈕與管理功能暫時隱藏
  ├─ 幽靈全程在標題下來回移動（即使已經完結，回放時也要出現）
  ├─ 天數從 0（2026-10-13）開始，一天一天往上跳
  │    ├─ 沒有記錄的日子：快速帶過
  │    └─ 有記錄的日子：停下來，跳出 RPG 對話框逐字顯示
  │         「10/23（五）提出：是　執行：否
  │           ── 颱風假」
  │         停留約 3 秒，或按任意鍵／點一下立刻跳下一則
  └─ 播到最後
       ├─ 已完結：播放完結演出（幽靈淨化、「— 全劇終 —」）
       └─ 連載中：天數跳到今天，顯示「（未完待續）」，回到目前畫面
```

**時間規則：**
- 播放順序依記錄的 `date`，**不是**寫入時間 `updatedAt`。補記的記錄會出現在它日期所在的位置。
- 沒有記錄的日子，推進速度約每天 0.2 秒；如果空白日子很多，自動加快，讓空白日子加總不超過 20 秒。
- 對話框的逐字速度約每字 40ms 【建議】。

**控制：**
- 暫停／繼續（空白鍵）
- 下一則（→ 或點對話框）
- 2 倍速切換
- 結束回放（Esc 或「✕ 結束」按鈕），回到原本畫面

**限制：**
- 回放只用 `/api/state` 已經取得的 `records`，不新增 API、不呼叫任何寫入 API、不改變任何資料。
- 回放期間背景同步（FR-10）照常進行，但新資料等回放結束後才套用到畫面，不打斷回放。
- 開啟「減少動態效果」時不自動播放：改成手動按「下一則」逐筆前進，天數直接跳到該筆的值，幽靈靜止。
- 手機上的控制按鈕要夠大，可以用手指點（最小 44×44px）。

## 7. API 規格 【規定】

Base URL 由前端建置變數 `VITE_API_BASE` 提供（例如 `https://move-or-not-api.up.railway.app`）。

所有路徑中的 `{seasonId}` 為季別代號，第一季為 `season-1`。本文件其他章節提到的 `/api/state`、`PUT /api/records/{date}` 等，皆為對應季別端點的簡寫。

### 7.1 `GET /api/health`

回 `200 {"ok": true}`。給 Railway 健康檢查用。

### 7.2 `GET /api/seasons`

不需驗證。回傳季別清單（依 `seasons.config.json` 順序，最後一筆為最新一季）。

```json
{
  "seasons": [
    {"id": "season-1", "startDate": "2026-10-13", "ended": false, "endedDate": null}
  ]
}
```

### 7.3 `GET /api/seasons/{seasonId}/state`

不需驗證。回應標頭 `Cache-Control: no-store`。季別不存在回 `404`。

```json
{
  "seasonId": "season-1",
  "serverNow": "2026-10-30T10:15:30+08:00",
  "timezone": "Asia/Taipei",
  "today": "2026-10-30",
  "startDate": "2026-10-13",
  "daysElapsed": 17,
  "ended": false,
  "endedDate": null,
  "todayRecord": null,
  "records": [
    {"date": "2026-10-28", "proposed": true, "executed": false, "note": "主管、管理部、總經理喬不攏", "updatedAt": "..."},
    {"date": "2026-10-23", "proposed": true, "executed": false, "note": "颱風假", "updatedAt": "..."},
    {"date": "2026-10-13", "proposed": true, "executed": false, "note": "起始日", "updatedAt": "..."}
  ],
  "stats": {"proposedCount": 3, "executedCount": 0, "successRate": 0},
  "lastUpdatedAt": "2026-10-28T18:00:00+08:00"
}
```

- `records` 依日期新到舊排序。
- `daysElapsed` 依 §4.2、§4.4 計算（伺服器端也算一次，前端以伺服器值為初始值）。
- `ended`／`endedDate`：是否已完結、完結日（即 §4.4 的「搬家日」）。欄位名稱刻意不用主題字詞，讓每一季通用。

### 7.4 `POST /api/auth/check`

標頭 `Authorization: Bearer <密語>`。正確回 `204`；錯誤回 `401`。密語跨季通用。

### 7.5 `PUT /api/seasons/{seasonId}/records/{date}`

需驗證。新增或覆蓋該季該日的記錄。

Request body：

```json
{"proposed": true, "executed": false, "note": "又說下週"}
```

`note` 的三種寫法：

| 送出內容 | 效果 |
|---|---|
| 不帶 `note` 或 `null` | 新增時為空字串；覆蓋時**保留原備註**（「提了」選單備註留空時用這個） |
| `""`（空字串） | 清空備註（管理模式用） |
| 一般字串 | 改成該內容 |

| 狀況 | 回應 |
|---|---|
| 成功 | `200`，回傳該筆記錄 |
| 密語錯誤或缺少 | `401` |
| 季別不存在 | `404` |
| `date` 格式錯、早於該季起始日、晚於台灣今天 | `422` |
| `executed=true` 但 `proposed=false` | `422` |
| `note` 超過 100 字 | `422` |
| 驗證失敗次數過多 | `429` |

### 7.6 `DELETE /api/seasons/{seasonId}/records/{date}`

需驗證。成功 `204`；季別或記錄不存在 `404`。

### 7.7 `GET /api/seasons/{seasonId}/export`

需驗證。下載該季完整資料檔（備份用）。

### 7.8 錯誤格式

```json
{"error": {"code": "EXECUTED_REQUIRES_PROPOSED", "message": "執行為「是」時，提出必須為「是」"}}
```

- `code` 為固定的英文代碼，前端依 `code` 從劇本設定檔取出要顯示的文字（§3.3 規則 1）；劇本沒有對應文字時，才顯示 `message`。
- API 的 `message` 用中性的繁體中文，不含任何主題字詞。

| code | 情境 |
|---|---|
| `UNAUTHORIZED` | 密語錯誤或缺少 |
| `TOO_MANY_ATTEMPTS` | 驗證失敗次數過多 |
| `SEASON_NOT_FOUND` | 季別不存在 |
| `RECORD_NOT_FOUND` | 記錄不存在 |
| `INVALID_DATE` | 日期格式錯或超出範圍 |
| `EXECUTED_REQUIRES_PROPOSED` | 執行為是但提出為否 |
| `NOTE_TOO_LONG` | 備註超過 100 字 |
| `DATA_FILE_ERROR` | 資料檔讀取失敗 |

## 8. 非功能需求

### 8.1 安全 【規定】

| 編號 | 要求 |
|---|---|
| NFR-S1 | 管理密語只存在 Railway 環境變數 `ADMIN_PASSPHRASE`，長度至少 16 字元；不得出現在 repo、前端打包檔、log 中 |
| NFR-S2 | 比對密語用常數時間比較（`hmac.compare_digest`） |
| NFR-S3 | 同一來源 IP 10 分鐘內驗證失敗 5 次 → 回 429（`TOO_MANY_ATTEMPTS`）；計數只存在記憶體，不寫檔。第一季畫面文案：「你試太多次了，跟搬家一樣，等等再說。」（放在劇本設定檔） |
| NFR-S4 | CORS 只允許環境變數 `ALLOWED_ORIGINS` 列出的來源（例如 `https://<帳號>.github.io`，注意 origin 不含路徑） |
| NFR-S5 | 寫入類 API 只接受 `application/json` |
| NFR-S6 | 前端輸出使用者輸入一律用 `textContent` |
| NFR-S7 | `.env`、任何含密語的檔案列入 `.gitignore` |

### 8.2 效能 【建議】

- 首頁 JS（不含字型）gzip 後 < 400KB；PixiJS 只 import 用到的模組。
- 字型 woff2 自行託管、`font-display: swap`。
- 手機中階機型維持 60fps；背景粒子數量依螢幕大小調整。

### 8.3 相容性 【規定】

需在以下環境正常運作：LINE 內建瀏覽器（iOS、Android）、iOS Safari、Android Chrome、桌機 Chrome／Edge／Safari／Firefox 最新版。最小寬度 360px。

### 8.4 無障礙 【規定】

- 今日狀態區塊加 `aria-live="polite"`。
- 選單可完全用鍵盤操作，焦點可見。
- 文字與背景對比至少 4.5:1。
- 幽靈 canvas 設 `aria-hidden="true"`。

### 8.5 部署環境變數

**Railway（api）**

| 變數 | 範例 | 說明 |
|---|---|---|
| `ADMIN_PASSPHRASE` | （自行產生） | 管理密語 |
| `ALLOWED_ORIGINS` | `https://<帳號>.github.io` | 多個用逗號分隔；本機開發可加 `http://localhost:5173` |
| `DATA_DIR` | `/data` | 各季資料檔放在 `${DATA_DIR}/seasons/`。未設定時改讀 Railway 自動提供的 `RAILWAY_VOLUME_MOUNT_PATH`；都沒有時用 `./data`（本機開發） |

> 起始日與天數算法不是環境變數，寫在 `api/seasons.config.json`（§5.0）。

**GitHub（web，建置時）**

| 變數 | 範例 | 存放位置 |
|---|---|---|
| `VITE_API_BASE` | `https://move-or-not-api.up.railway.app` | Repo → Settings → Secrets and variables → Actions → **Variables**（不是機密） |

## 9. 視覺風格規格

### 9.1 風格方向 【規定】

**16-bit（超任 SNES 世代）日式角色扮演遊戲**，不是 8-bit 紅白機風。關鍵特徵：

- 藍色漸層、白色外框的「對話視窗」作為所有資訊區塊的容器。
- 夜空背景：深藍到紫的漸層，像素星星閃爍，緩慢視差移動。
- 所有圖像整數倍放大、`image-rendering: pixelated`。
- 可選的 CRT 掃描線效果（預設開、可在頁尾關閉）【建議】。

### 9.2 色票 【建議】

| 用途 | 色碼 |
|---|---|
| 背景深色 | `#0b0f2a` |
| 背景漸層亮端 | `#2a1f5c` |
| 視窗漸層上 | `#3048b8` |
| 視窗漸層下 | `#101c68` |
| 視窗外框 | `#f8f8f8`（外側再包 `#000000` 1px） |
| 主文字 | `#f8f8f8` |
| 強調（天數數字、游標） | `#f8d850` |
| 是 | `#58d858` |
| 否 | `#f85858` |
| 幽靈 | `#ffffff`，眼睛 `#202040` |

### 9.3 文案語氣 【建議】

詼諧、帶點無奈，不罵人、不指名。範例：

- 讀取中：「讀取存檔中……（跟搬家進度一樣慢）」
- 0 次搬成功時統計旁小字：「本季 KPI：搬家。進度：載入中。」
- 跨日時天數跳動後短暫顯示：「又過了一天。」
