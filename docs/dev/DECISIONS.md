## D-01 不提供 robots.txt，只用 meta robots

- **對應條文**：SRS §2-5
- **決策**：不做 `robots.txt`，只在頁面加上 `<meta name="robots" content="noindex, nofollow">`。
- **理由**：專案網站（`/move-or-not/`）的 robots.txt 不在網域根目錄，爬蟲不會讀取；而且被 robots.txt 擋下的頁面，爬蟲讀不到 noindex，反而無效。

## D-02 commit 作者使用不具名設定

- **對應條文**：SRS §2
- **決策**：commit 作者使用 repo 層級的不具名 git 設定（`move-or-not` ／ `move-or-not@example.invalid`）。GitHub 帳號名稱出現在網址中，為已知並接受的限制。每次 commit 前確認 `git config user.name`／`user.email` 未被改回。
- **理由**：commit 紀錄是公開的，作者欄位不應帶出可識別的身分。

## D-03 日期欄位用原生 date input，旁邊另顯示格式化文字

- **對應條文**：SRS FR-06（日期欄位）
- **決策**：使用原生 `<input type="date">` 並設定 `min`／`max`；欄位旁另以文字顯示 `MM/DD（週X）`。
- **理由**：原生欄位的顯示格式由瀏覽器語系決定，無法自訂，只能另外顯示規格要求的格式。

## D-04 前端建置時打包季別日期，只供退路模式使用

- **對應條文**：SRS §4.1-5、§4.2
- **決策**：
  - 前端建置時（含 dev server）從 repo 內的 `api/seasons.config.json` 讀取各季 `startDate`、`countInclusive` 並打包進前端，**只供退路模式（API 連不上時）使用**；正常情況仍以 API 回傳值為準。
  - 原始設定只有 `seasons.config.json` 一份，不得在前端手動重複設定。
  - 退路模式無法得知是否已完結，此時天數**不凍結**，以「⚠ 時間來源：本機時鐘」標示，接受此限制。
- **理由**：退路模式需要起始日才能算天數，從同一份設定檔自動帶入可避免兩處設定不一致。

## D-05 已完結但今天沒有記錄時的今日狀態

- **對應條文**：SRS FR-05
- **決策**：已完結、但今天沒有記錄（完結日不是今天）時，今日狀態改顯示「已於 MM/DD（週X）完結」類文案。文字放劇本設定檔；第一季文案由 RD 提案、SA 在 PR 審。
- **理由**：完結後顯示「今天還沒人提」與完結狀態矛盾，需要專屬文案。

## D-06 定期更新失敗的容錯

- **對應條文**：SRS FR-10、FR-11
- **決策**：初次讀取成功後，定期更新失敗時保留畫面資料與 offset，頁尾顯示小提示；**連續**失敗達設定次數（預設 3 次，集中在設定檔）後，才切換到 FR-11 錯誤畫面。
- **理由**：偶發的網路失敗不應讓已正確顯示的畫面整個變成錯誤狀態。

## D-07 管理模式的日期欄位與覆蓋確認

- **對應條文**：SRS FR-08
- **決策**：
  - 管理模式**編輯**記錄時，日期欄位鎖定不可修改；要更改日期，由管理者先刪除、再新增。
  - 管理模式**新增**記錄時，若該日期已有記錄，比照 FR-06 顯示原內容，確認後才覆蓋。
- **理由**：日期是主鍵，編輯時改日期等於「刪一筆＋寫一筆」，拆成兩個明確動作可避免誤蓋其他日期的記錄。

## D-08 管理模式提供下載備份

- **對應條文**：SRS §7.7
- **決策**：管理模式提供「下載備份」按鈕，呼叫 export 端點。
- **理由**：讓管理者不需要 Railway CLI 也能隨時備份。

## D-09 備註字數計算與單行限制

- **對應條文**：SRS §5.1（`note` 欄位規則）
- **決策**：備註字數前後端一律以 **Unicode code point** 計算（去頭尾空白後 ≤ 100）。只允許單行；含換行或控制字元時回 `422`，code 為 `INVALID_REQUEST`。
- **理由**：JavaScript 字串長度以 UTF-16 code unit 計算、Python 以 code point 計算，必須統一定義才不會前後端判斷不一致。

## D-10 Content-Type 檢查範圍

- **對應條文**：SRS NFR-S5
- **決策**：`Content-Type` 檢查只套用在有 body 的寫入請求（`PUT`）；`DELETE` 與 `POST /api/auth/check` 不檢查。
- **理由**：沒有 body 的請求不存在內容格式問題，強制檢查只會增加前端負擔。

## D-11 減少動態效果時的其他動態

- **對應條文**：SRS FR-02、§9.1、§8.4
- **決策**：開啟減少動態效果時：主角依 FR-02；星空閃爍、視差、粒子、跳數字、CRT 動態改為「**減弱**」（降低速度、幅度或數量），不完全停止。
- **理由**：保留風格氛圍，同時降低對動態敏感使用者的負擔。

## D-12 音效與 CRT 開關

- **對應條文**：SRS Q-03、§9.1
- **決策**：
  - 音效開關預設靜音，用 Web Audio API 即時合成，不使用音檔；音效參數放劇本設定檔。
  - CRT 與音效開關**不保存**（不用 localStorage），每次進站回到預設值。
- **理由**：即時合成不必託管音檔、也方便各季替換；不保存設定則符合 FR-10 不使用 localStorage 的原則。

## D-13 部署文件與網站網址變數

- **對應條文**：部署（SRS §8.5、FR-12）
- **決策**：
  - `docs/DEPLOY_GUIDE.md` 由 SA 撰寫初版，RD 在階段 7 依實作結果更新，並在 PR 中列出所有修改。
  - 新增前端建置變數 `VITE_SITE_URL`（網站完整網址，供 `og:image`、`og:url` 的絕對網址使用），存放於 GitHub repo 的 Actions **Variables**。
- **理由**：分享預覽需要絕對網址，而網址取決於部署帳號，不能寫死在 repo。

## D-14 Windows 開發環境支援

- **對應條文**：開發環境（CLAUDE.md §7、§8）
- **決策**：
  - SA 使用 Windows PowerShell。
  - 前端 API 位址改用 `web/.env.local` 設定（範本 `web/.env.example`）。
  - README 同時提供 bash 與 PowerShell 的啟動指令。
  - `check-deid` 與 AC-30 檢查腳本都提供 `.sh` 與 `.ps1` 兩個版本。
- **理由**：`VAR=value command` 是 bash 語法，PowerShell 不支援，改用檔案設定兩邊都能用。

## D-15 新增錯誤代碼

- **對應條文**：SRS §7.8
- **決策**：錯誤代碼新增兩個：
  - `INVALID_REQUEST`：body 格式或型別錯誤、備註含換行或控制字元時回 `422`；`Content-Type` 不是 JSON 時回 `415`。
  - `INTERNAL_ERROR`：未預期錯誤，回 `500`。
  - API 的 `message` 同樣使用中性文字。
- **理由**：SRS 的代碼表沒有涵蓋這些情境，前端需要固定代碼才能從劇本取文案。

## D-16 圖檔由一次性產圖腳本產出

- **對應條文**：SRS §3.3 規則 2、FR-12
- **決策**：主角 sprite sheet、og:image、favicon 由 RD 撰寫一次性產圖腳本（放 `tools/`）產出 PNG 後 commit。執行期只讀取外部圖檔；產圖腳本不得被前端打包引用。日後可直接換成正式美術。
- **理由**：目前沒有美術資源，用腳本產出可重現的暫用圖，同時遵守「不得用程式碼繪製角色」的執行期規定。

## D-17 共用介面文字

- **對應條文**：SRS §3.3 規則 1
- **決策**：與季別無關的介面文字（重試、登出、編輯、刪除、回放控制等）放在 `web/src/stories/common.ts`，各季劇本可覆寫。`StoryConfig` 型別同時涵蓋兩者，少填欄位時編譯失敗。
- **理由**：避免每季重複填寫相同的介面文字，同時保留各季客製的彈性。

## D-18 回放的按鍵配置

- **對應條文**：SRS FR-13（控制）
- **決策**：回放中：
  - 空白鍵＝暫停／繼續；Esc＝結束。
  - Tab、Shift+Tab 在控制列之間移動焦點；焦點在控制列按鈕上時，Enter 觸發該按鈕。
  - Shift、Ctrl、Alt、Meta 單獨按下時不動作。
  - 其餘按鍵＝下一則。
  - 2 倍速只提供按鈕，不綁定按鍵。
- **理由**：與 FR-13「按任意鍵立刻跳下一則」一致，同時保留鍵盤使用者操作控制列的能力（§8.4）。
- **修訂**：2026-10-30 依 SA 回覆 PR #1（Q-RD-06）修訂。原決策為「空白鍵＝暫停／繼續，Esc＝結束，其他任何按鍵＝下一則」。

## D-19 回放期間的畫面區塊

- **對應條文**：SRS FR-13
- **決策**：回放期間隱藏統計、今日狀態、記錄表三個區塊，以及頁尾的 🔑 管理入口；頁尾其餘內容（免責聲明等）保持顯示，以符合 SRS §2-4。
- **理由**：統計與記錄是「現在」的資料，和回放中的時間點不一致，會造成混淆；免責聲明則依 §2-4 必須常駐。
- **修訂**：2026-10-30 依 SA 回覆 PR #1（Q-RD-07）修訂。原決策為「只保留標題、主角、天數、對話框與回放控制列」（頁尾也會隱藏）。

## D-20 已完結時回放的範圍

- **對應條文**：SRS FR-13、§4.4
- **決策**：已完結時，回放只播到完結日（`endedDate`），之後的記錄不播，直接接完結演出。統計與記錄表照 SRS 計入全部記錄。
- **補充（AC-24 的解讀）**：SRS AC-24 的「每一筆記錄」，在已完結時解讀為「完結日（含）以前的每一筆記錄」。AC-24 的自動化測試照此撰寫，並另加一條測試，確認完結日之後的記錄不會播出。
- **理由**：劇情在完結日結束，之後的記錄放在完結演出前面會打亂敘事。
- **修訂**：2026-10-30 依 SA 回覆 PR #1（Q-RD-08）補充 AC-24 的解讀，原決策內容不變。

## D-21 完結後的進站演出

- **對應條文**：SRS §4.4
- **決策**：完結後每次進站播放一次**短版**完結演出（約 2 秒），之後停在完結畫面（「— 全劇終 —」與回放按鈕）。開啟減少動態效果時直接顯示完結畫面。
- **理由**：讓之後才進站的訪客也看得到結局，但不必每次等完整演出。

## D-24 來源 IP 讀取 X-Real-IP

- **對應條文**：SRS NFR-S3；來源 PR #1 Q-RD-02
- **決策**：
  - 來源 IP 預設讀取 `X-Real-IP` 標頭；沒有這個標頭時，使用連線 IP。讀取方式集中在設定檔。
  - 階段 7 部署後實測：連續送 6 次錯誤密語，每次偽造不同的 `X-Real-IP`；第 6 次仍回 `429`，即代表 Railway 會覆寫此標頭。結果寫進 DEPLOY_GUIDE。
  - 若實測發現此標頭會被偽造，停下來回報 SA。
- **理由**：Railway 官方文件只列出 `X-Real-IP` 作為客戶端 IP，但沒有說明是否會覆寫客戶端自帶的值，只能部署後實測確認。

## D-25 驗證失敗的計數與封鎖

- **對應條文**：SRS NFR-S3、AC-09；來源 PR #1 Q-RD-03
- **決策**：同一來源 IP 在 10 分鐘滑動視窗內，第 1～5 次驗證失敗回 `401`。之後在計數過期前，該 IP 的任何需驗證請求一律回 `429`（`TOO_MANY_ATTEMPTS`），不比對密語，密語正確也一樣。
- **理由**：封鎖期間若仍比對密語，等於讓猜中的那一次照樣通過，次數限制就失去作用。

## D-26 DELETE 的日期檢查

- **對應條文**：SRS §7.6；來源 PR #1 Q-RD-09
- **決策**：DELETE 的日期格式錯誤回 `422`（`INVALID_DATE`）。格式正確時不檢查是否在範圍內，照常查詢：記錄不存在回 `404`（`RECORD_NOT_FOUND`），存在就刪除。
- **理由**：日後若調整起始日，範圍外的舊記錄仍刪得掉。

## D-27 起始日在未來的季別

- **對應條文**：SRS §4.2；來源 PR #1 Q-RD-10
- **決策**：起始日在未來的季別，`daysElapsed` 最小為 0；寫入時日期範圍為空，照 §7.5 回 `422`。季別尚未開始時的畫面不在本次範圍。
- **理由**：避免天數出現負數，又不必在本次設計「尚未開始」的畫面。
