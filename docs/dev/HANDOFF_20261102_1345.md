## 3. 已知問題與未解疑問

- **Railway 的啟動指令**：專案進入點是 `app/main.py`，Railpack 的自動偵測不適用，必須在介面填 `uvicorn app.main:app --host 0.0.0.0 --port $PORT`。RD 看不到 SA 目前填的值，請 SA 合併前確認。
- **啟動檢查變嚴格**：
  - `ADMIN_PASSPHRASE` 缺少、少於 16 字元、或含非 ASCII 字元時，服務不會啟動。
  - `ALLOWED_ORIGINS` 缺少，或含路徑、結尾斜線、`*` 時，服務也不會啟動。
  - Railway 上的值不符合時，這次部署會失敗。
- **未知路徑**（例如 `/api/nope`）回 FastAPI 預設的 `{"detail": "Not Found"}`，不是 §7.8 格式。SRS 的代碼表沒有「路徑不存在」，而且前端不會呼叫這類路徑，所以沒有新增代碼（見 PR 的差異說明）。
- **U+FEFF**：後端不把它當空白（D-28 的「一般空白字元」解讀為 Unicode Zs）。JavaScript 的 `trim()` 會去掉 U+FEFF，階段 4 前端不能直接用 `trim()`，要依 `note-cases.json` 實作。
- **本機 Python**：仍由 uv 提供（`api/.venv`，3.12.13）。
- 待回覆的疑問：Q-RD-04、05、11～14（依各階段開工時間）。

## 5. 與 SRS 不一致、等待 SA 回覆的事項

以下是本階段比 SRS 多做或自行解讀的地方，詳見 PR 的差異說明，SA 不同意時可以調整：

- `ADMIN_PASSPHRASE` 限 ASCII（NFR-S1 只規定長度）。理由：瀏覽器的 `fetch` 不接受非 ASCII 的標頭值，非 ASCII 的密語會無法登入。
- `ALLOWED_ORIGINS` 啟動時檢查格式（NFR-S4 只要求「只允許列出的來源」）。
- 401 附 `WWW-Authenticate: Bearer`；429 附 `Retry-After`（秒）。
- 缺少 `Authorization` 標頭也算一次驗證失敗（NFR-S3 沒有區分「缺少」與「錯誤」，§7.4 把兩者都歸為 401）。
- `GET /api/seasons` 也加上 `Cache-Control: no-store`（§7.3 只要求 state）。
- 寫入時的檢查順序：密語 → 季別 → Content-Type（415）→ 日期 → body。
- 種子寫入不記 audit（§5.3 只列 API 寫入）。
