## 3. 已知問題與未解疑問

- **備註含換行的 8 筆共用案例**：`<input type="text">` 的值依 HTML 規格會去掉 CR／LF，使用者在畫面上無法輸入換行。這 8 筆只在 vitest 驗證（`normalizeNote` 直接拒絕）；Playwright 另有一條測試，確認貼上含換行的文字時送出的備註不含換行。其餘 23 筆在 Playwright 中逐筆透過選單送出。
- **無法放進 HTTP 標頭的密語**（非 ASCII 等）：前端不送出請求，直接顯示密語錯誤；因此這種輸入不會計入後端的失敗次數（D-25）。後端本來就只接受可見 ASCII 與空白（D-37 第 1 項）。
- **下載備份不自動重試**：export 雖然是 GET，但屬於需要密語的請求，和寫入一樣只送一次。D-40 規定「重試只適用於 GET」，沒有要求每個 GET 都要重試。
- **寫入後 401**（密語在伺服器端被更換）：前端清除 sessionStorage 的密語並顯示錯誤，下次操作會重新詢問；管理模式不會自動退出。
- **Windows 本機的 Playwright 下載**：在本機讀取 Playwright 的下載暫存檔會出現 EPERM，所以備份測試改在頁面內記下交給下載的 Blob 內容，同時仍驗證 `download` 事件與檔名。
- **AC-18 的 15 秒測試**（階段 3）：在完整平行執行時偶爾失敗。原因是時鐘沒有暫停，機器負載會讓真實時間多走。已改成先暫停時鐘，連續重跑都通過。
